# SOA-20261118-09 — Wallet token atomik dan AI usage aktual

## Ruang lingkup

Milestone ini melanjutkan backend Express + Sequelize + MySQL dan frontend Laravel Blade. Pembelian paket/token dan webhook Midtrans yang sudah ada tetap dipakai. Wallet lama yang hanya memiliki `balance` ditingkatkan secara additive: saldo tersedia dan saldo reservasi menjadi sumber kebenaran, sedangkan `balance` dipertahankan sebagai alias kompatibilitas untuk katalog lama.

## 1. Model dan relasi

- `User.hasOne(TokenWallet)` / `TokenWallet.belongsTo(User)`; `token_wallets.user_id` adalah primary key sehingga unik.
- `TokenWallet.hasMany(TokenLedger)`; ledger juga memiliki relasi owner dan purchase.
- `User.hasMany(AIUsage)` / `AIUsage.belongsTo(User)`.
- `AIUsage` memiliki unique `(user_id, idempotency_key)`.
- `TokenLedger` tidak paranoid dan tidak mempunyai CRUD publik. Ledger pembelian memiliki unique `token_purchase_id`; event lain memakai unique `event_key`.
- Token disimpan sebagai integer/bigint unsigned dengan batas layanan 2.147.483.647 unit. `available_tokens` dan `reserved_tokens` tidak boleh negatif.

Status AIUsage: `reserved`, `completed`, `failed`, `needs_reconciliation`. Ledger mencatat `credit`, `debit`, `reserve`, `release` dengan status audit.

## 2. Transaksi wallet

`js/src/services/tokenWallet.js` menyediakan:

- `reserve`: lock row user dan wallet, cek saldo, pindahkan saldo tersedia ke ditahan, lalu buat AIUsage dan ledger reserve dalam satu transaksi.
- `commitUsage`: lock usage dan wallet, hitung `input_tokens + output_tokens`, debit aktual, lepaskan selisih reservasi, tulis ledger debit/release, dan finalisasi satu kali.
- `release`: mengembalikan reservasi hanya untuk kegagalan yang aman dilepas sebelum dispatch.
- `grantPurchase`: mengkredit snapshot kuota setelah purchase paid. Dipanggil dari transaksi webhook Midtrans yang sama; unique purchase ledger dan row lock mencegah replay kredit.
- `markNeedsReconciliation`: mempertahankan reservasi ketika provider mungkin sudah memproses request tetapi hasil/metadata tidak pasti.

Tidak ada transaksi database yang dibiarkan terbuka saat menunggu provider AI. Row lock dan unique key melindungi request bersamaan. Jika aktual melebihi reservasi dan saldo tambahan tidak cukup, status menjadi `needs_reconciliation`, bukan memaksa saldo negatif.

## 3. AI request pipeline

Urutan: JWT + sesi aktif → `X-API-Key` milik user yang sama → tier/rate limit dan log W8 → validasi body/idempotency → konteks transaksi owner → estimasi reservasi → panggilan provider → validasi metadata → commit/reconciliation.

Provider dikonfigurasi hanya di Node `.env`. Koleksi uji tersedia pada `postman/ProjectSOA-AI-Wallet.postman_collection.json` dan environment template pada `postman/ProjectSOA-AI-Wallet.postman_environment.json`.

Konfigurasi Node:

```dotenv
AI_PROVIDER_BASE_URL=https://api.openai.com/v1
AI_PROVIDER_API_KEY=
AI_MODEL=gpt-4o-mini
API_TIMEOUT_MS=30000
```

`POST /ai/api-key` menerbitkan kunci aplikasi satu kali; hanya hash SHA-256 disimpan di `api_clients`. Laravel menyimpan kunci aplikasi dalam session server. Pengguna tidak memasukkan provider key. Kunci AI tidak boleh dikirim ke browser. Rate limit menggunakan `api_tiers`, `api_clients`, dan `api_log`.

Analisis menggunakan data transaksi pada periode `YYYY-MM` dengan filter `id_user=req.user.id`. Pilihan jawaban dipetakan server: singkat 250 token output, normal 700, rinci 1.400. Reservasi memperhitungkan prompt lengkap (instruksi + konteks + pertanyaan), batas output, dan margin 20%; estimasi hanya untuk reservasi, bukan debit aktual. Prompt yang melewati preflight ditolak sebelum dispatch.

Debit MVP = `prompt_tokens + completion_tokens`. `total_tokens` provider disimpan terpisah; thinking/cache/tool juga metadata terpisah dan tidak dijumlahkan lagi ke debit. Cached tokens yang sudah tercakup dalam `prompt_tokens` tidak dihitung dua kali.

`Idempotency-Key` sama + prompt hash sama: jika request telah completed, server mengembalikan jawaban lama tanpa debit baru. Key sama dengan prompt berbeda menghasilkan 409. Request reserved/ambiguous tidak dipanggil ulang otomatis. Timeout/provider metadata hilang menjadi `needs_reconciliation` dan kuota tetap ditahan.

## 4. Pemulihan reservasi

Setiap reservasi memiliki `reservation_expires_at` dan `dispatch_started_at` dicatat dalam transaksi terpisah sebelum koneksi provider dimulai. Pelepasan default menolak usage yang sudah dispatch; hanya respons penolakan provider yang definitif yang dapat melepas setelah dispatch. `POST /api/v1/admin/ai/reconcile-expired` hanya untuk admin:

- Reservasi kedaluwarsa tanpa `dispatch_started_at` dilepas.
- Reservasi yang sudah dispatch tidak dilepas otomatis; ditandai `needs_reconciliation` karena provider mungkin telah memprosesnya.

Endpoint ini adalah mekanisme pemeriksaan, bukan retry provider. Jalankan terjadwal oleh operator setelah menguji environment dan kebijakan operasional.

## 5. Endpoint

Semua endpoint berikut memakai prefix `/api/v1`.

| Method | Path | Tujuan |
|---|---|---|
| GET | `/token-wallet` | Saldo tersedia/ditahan/total |
| GET | `/token-ledger` | Riwayat audit, filter jenis/tanggal, pagination |
| POST | `/ai/api-key` | Terbitkan API key aplikasi satu kali (JWT) |
| POST | `/ai/analyze` | Analisis AI, wajib JWT + X-API-Key + Idempotency-Key |
| GET | `/ai/usages` | Riwayat per request, filter status/tanggal, pagination |
| GET | `/ai/usage-summary?period=YYYY-MM` | Rekap input/output/total aktual |
| GET | `/ai/wallet` | Saldo wallet melalui kontrak AI key |
| GET | `/ai/ledger` | Ledger melalui kontrak AI key |
| POST | `/admin/ai/reconcile-expired` | Pemeriksaan reservasi kedaluwarsa (admin) |

Status penting: 409 saldo kurang/konflik idempotency, 429 rate limit, 202 needs reconciliation, 502/504 upstream tidak pasti. Jangan otomatis mengulang panggilan berbayar setelah timeout.

## 6. UI Laravel

- `/app/token-wallet`: kartu tersedia/ditahan/total, rekap bulanan input/output, ledger dengan filter dan pagination, riwayat penggunaan dengan filter status dan pagination. Saldo nol menampilkan tautan katalog.
- `/app/ai-analysis`: periode, pertanyaan, panjang jawaban, konteks finansial dari server sesuai owner, hasil teks ter-escape, input/output aktual dan saldo tersisa.
- Label status: Proses, Selesai, Gagal, Perlu pemeriksaan. Kuota tidak memakai simbol Rupiah dan tidak ada form untuk mengubah saldo.
- Output AI ditampilkan sebagai teks, bukan HTML mentah. UI tidak menyimpan provider key atau mengulang request otomatis.

## 7. Upgrade dan pengujian

Dari folder `js/`:

```powershell
npm ci
npm run db:migrate
npm run test:ai-wallet
npm test
npm run test:mysql
```

Isi `AI_PROVIDER_API_KEY` hanya di environment backend Node bila ingin menguji provider nyata. Jangan commit `.env`. `npm run db:migrate` additive: menambah kolom wallet/ledger dan tabel ai_usages tanpa reset data lama. `balance` lama dipindahkan ke `available_tokens` ketika kolom baru masih nol.

Unit test `tests/ai-wallet.test.js` memverifikasi contoh 100 input + 50 output = 150 dan perhitungan reservasi. Test MySQL terisolasi (aktif pada `RUN_MYSQL_TESTS=1`) memeriksa concurrency reserve, idempotency, commit, release, rollback, grantPurchase replay, dan saldo nonnegatif. Provider nyata tetap memerlukan kredensial serta koneksi provider; tidak diklaim lolos tanpa konfigurasi tersebut.

## Batasan yang diketahui

- Adapter menggunakan format OpenAI-compatible `/chat/completions`; provider yang tidak kompatibel perlu adapter khusus.
- Penghitungan prompt untuk reservasi adalah estimasi konservatif berdasarkan byte UTF-8/3, bukan tokenizer provider. Penagihan tetap berdasarkan metadata aktual provider.
- `needs_reconciliation` membutuhkan pemeriksaan operator; sistem tidak menebak pemakaian token ketika metadata tidak tersedia.
- API key aplikasi disimpan dalam session Laravel server; ketika session baru meminta key, key aktif sebelumnya untuk owner yang sama dicabut dan diganti.
