# SOA-20261106-05 — Katalog token dan order lokal

Status implementasi: katalog dan order lokal tersedia. Pembayaran, wallet/ledger,
penambahan kuota, subscription bulanan dan perubahan tier W8 belum aktif.
Dependency yang dipakai adalah User, JWT/AuthSession/role dan koneksi Sequelize
yang sudah ada dalam ZIP sumber. Tidak dibuat database akun kedua.

## Menjalankan

1. Simpan `.env` milik tim di luar ZIP/commit. Gunakan database lama yang sama.
2. Root backend: `npm ci`, `npm run db:migrate`.
3. Opsional pada pengembangan: `npm run db:seed:tokens`.
4. Daftarkan akun via aplikasi. Untuk admin yang dipercaya, jalankan
   `npm run user:admin -- email-akun-admin` dari terminal backend.
5. Root: `npm run dev`. Terminal kedua di `laravel-web`: `composer install`,
   `php artisan optimize:clear`, `php artisan serve --host=127.0.0.1 --port=8000`.
   Ikuti konfigurasi awal APP_KEY/SOA_API_BASE_URL pada README jika instalasi baru.
6. Login user untuk membuka `/app/token-bundles`. Login admin untuk menu
   `/app/admin/token-bundles` dan `/app/admin/categories`.

Migration `sql/migrations/20261106_05_tokens.sql` dipanggil oleh runner lama,
setelah skema dasar. Hanya dua tabel baru, tanpa reset data atau sync force/alter.
Untuk SQLyog, jalankan migration tambahan itu di database lama setelah skema
dasar sudah tersedia; runner tetap pilihan utama untuk seluruh upgrade.

Paket seed: DEMO Hemat (1.000 token/Rp15.000), DEMO Rutin
(5.000/Rp65.000), DEMO Ekstra (12.000/Rp140.000). Harga hanya contoh tugas.
Seed eksplisit, ditolak pada NODE_ENV=production, aman diulang, tidak
menghidupkan kembali paket arsip atau menimpa harga yang diedit.

## Model dan histori

| Model | Kontrak |
| --- | --- |
| TokenBundle | name dinormalisasi trim + gabung spasi oleh setter; token_quota integer 1–2.147.483.647; price_idr DECIMAL(15,2) positif; is_active boolean; paranoid:true |
| TokenPurchase | order_id unik; user_id dari JWT; token_bundle_id; status default pending; snapshot nama/harga/kuota; currency IDR; idempotency_key unik per user; histori tidak dihapus |

User.hasMany TokenPurchase (`token_purchases`); TokenPurchase.belongsTo User
(`user`) dan TokenBundle (`bundle`); TokenBundle.hasMany purchases (`purchases`).
FK user memakai INT signed seperti users.id, FK bundle INT unsigned. Budget–
Category tetap N:M melalui BudgetCategory.

DELETE bundle mengarsipkan dengan is_active=false + deletedAt dalam transaksi.
GET order memakai include bundle paranoid:false, required:false sehingga paket
asal tetap terlihat setelah arsip. Tampilan finansial SELALU memakai snapshot,
bukan nama/harga/kuota katalog saat ini. Snapshot/identitas dilindungi hooks
instance/bulk-update, dan tidak tersedia endpoint edit/hapus purchase.
Kategori memakai kontrak lama: hanya kategori yang tidak direferensikan
transaksi/anggaran dapat dihapus; tidak ada soft delete kategori baru.

## REST API

Semua path di bawah diawali `/api/v1`, memerlukan Bearer JWT aktif.
Role ditentukan dari tabel users pada middleware, bukan klaim role body.
Harga JSON berupa STRING desimal, kuota JSON NUMBER integer, is_active BOOLEAN.
Field tak dikenal ditolak Joi, termasuk harga/kuota/status/pemilik purchase.

| Method | Path | Akses dan hasil |
| --- | --- | --- |
| GET | /token-bundles | User/admin; katalog aktif saja; data + meta |
| GET, POST | /admin/token-bundles | Admin; semua status / create 201 + Location |
| GET, PUT, PATCH, DELETE | /admin/token-bundles/:id | Admin; detail / ganti lengkap / sebagian / arsip 204 |
| GET, POST | /token-purchases | Hanya order pemilik JWT / buat lokal pending |
| GET | /token-purchases/:orderId | Hanya pemilik, termasuk histori paket arsip |
| GET, POST | /token-purchases/:orderId/checkout | GET 200 available:false; POST 503 belum tersedia |

Query katalog: limit 1–100 (default 12), offset >=0. Admin boleh status
all/active/inactive/archived. User tidak boleh meminta katalog arsip/nonaktif.
Query order: limit/offset dan status pending/paid/failed/cancelled/expired.
PUT bundle wajib empat field; PATCH minimal satu. Semua method lain pada
resource yang dikenal menghasilkan 405 + Allow; akses admin oleh user 403
dan tanpa JWT 401. Admin juga tidak dapat membaca order milik orang lain.

Contoh create/PUT admin:

```json
{"name":"DEMO Hemat","token_quota":1000,"price_idr":"15000.00","is_active":true}
```

Contoh order:

```http
POST /api/v1/token-purchases
Authorization: Bearer <access-token-pengguna>
Idempotency-Key: 89b9a0ca-5639-4cb1-96ac-dcf7e6c76a20
Content-Type: application/json

{"token_bundle_id":1}
```

Client tidak mengirim nominal/kuota/owner/status. Service mengunci row User,
memeriksa key, mengunci bundle aktif, dan membuat snapshot di SATU transaksi
InnoDB. Kunci unik (user_id,idempotency_key) menjadi pertahanan tambahan.
Key ASCII 8–80 karakter, case-sensitive, hanya huruf/angka/._:-.

Order baru: 201 + Location, Idempotency-Replayed:false. Key sama + bundle sama:
200, order/snapshot sama, Idempotency-Replayed:true, bahkan setelah paket
diarsipkan. Key sama + bundle berbeda: 409. Key baru + paket nonaktif/arsip:
404. Simpan/reuse key ketika status request belum diketahui.

Web menyimpan key per paket dalam session server. Refresh/back/double-click
mengembalikan order yang sama. Untuk pemesanan terpisah yang disengaja,
gunakan tombol “Siapkan order baru untuk paket ini” pada detail order;
tindakan itu hanya mengganti key form, lalu kembali ke katalog.

Postman: import `postman/ProjectSOA-Token-Lokal.postman_collection.json`.
Isi kredensial user/admin milik sendiri. Collection tidak memuat token/key
operasional. Jalankan permintaan berurutan untuk membuktikan snapshot tetap
sama sesudah harga diubah dan paket diarsipkan.

## UI dan keamanan

- Kartu pengguna dari API/database: nama, kuota, harga IDR, badge aktif dan
  tombol Beli paket. Tidak ada kontrol atau URL admin pada HTML user.
- Admin memakai DataTable/FormField bersama untuk paket dan kategori.
  Middleware Laravel mengecek role hasil GET auth/me, lalu API mengecek role DB
  lagi. Mengetik URL admin atau memodifikasi session role tidak memberi akses.
- Badge Aktif/Nonaktif/Arsip, Pending/Paid/Gagal/Dibatalkan/Kedaluwarsa,
  error field, empty-state, konfirmasi arsip/hapus dan tabel bergeser di mobile.
- Checkout adalah halaman status dengan tombol bayar disabled, tanpa redirect
  ke provider. Pending belum paid dan belum memberikan kuota.
- Form memakai CSRF; Blade melakukan escaping, termasuk nama paket dan ikon
  kategori. Tidak ada URL nominal/owner yang dipercaya. UI/API keuangan tidak
  masuk cache PWA; cache aset dinaikkan ke v3-token-catalog.

## Handoff Dana: service pembayaran dan kuota

`src/services/tokenCheckout.js` menyediakan kontrak:

| Fungsi server | Saat ini | Syarat implementasi berikutnya |
| --- | --- | --- |
| inspectCheckout({userId,orderId}) | Order milik pemanggil + available:false | Mengambil status checkout lokal/provider yang telah diverifikasi |
| startCheckout({userId,orderId}) | Validasi owner, lalu 503 | Gunakan snapshot/order_id; checkout provider idempotent; simpan token/provider ID server-side |
| grantPaidPurchase({orderId,paymentEventId,transaction}) | Selalu 503; tidak ada endpoint HTTP | Verifikasi signature/status/nominal/currency; lock order+wallet; ledger unik per purchase; tambah kuota dan paid secara atomik |

Wallet/ledger dan verifikasi event BELUM diimplementasikan. Jangan memanggil
grant dari browser return URL, menganggap redirect sukses sebagai paid, atau
mengubah tier/subscription saat membeli paket sekali beli. Callback duplikat,
amount mismatch, expired/failed dan dua settlement paralel harus dites pada
milestone Midtrans. Nama/harga/kuota snapshot tidak diubah service berikutnya.
